I reported a bug in Wallos, an open-source subscription manager. The two-factor authentication QR code did not appear when the username contained non-ASCII characters.

The report is [issue #1147](https://github.com/ellite/Wallos/issues/1147). The fix proposed there shipped in v5.4.5 on 23 August 2026 and is still present in v5.8.3.

The commit on main is [267f057](https://github.com/ellite/Wallos/commit/267f057bec332f29cb19e9478f20f0212baaf65c), a squash merge of [pull request #1175](https://github.com/ellite/Wallos/pull/1175). The commit message title is "fix: scope currency rate updates to the user being refreshed (#1175)". The body contains "fix: 2FA QR code fails for usernames with non-ASCII characters" and "Fixes #1147". The pull request title is "V5 6 0", and the pull request body is empty.

Line 44 of `endpoints/user/enable_totp.php` wraps the username in `rawurlencode()` when building the otpauth:// URL. That is the fix proposed in the issue. The bundled `qrcode.min.js` was not changed.

The pre-squash commit with only this change is [b79a3c8](https://github.com/ellite/Wallos/commit/b79a3c8dad818b71544a3f84561b68cc15a952d8). It is not in the main history.

The [v5.4.5 release notes](https://github.com/ellite/Wallos/releases/tag/v5.4.5) list it as "2FA QR code fails for usernames with non-ASCII characters (#1175) (267f057), closes #1147".
